# Current implementation scope

Working: multi-project setup, mandatory creator interview and content-fingerprinted approval for new real projects, English/French first-run prompts, three themes, nine layouts, native editable text/diagrams/arrows/charts, explicit CSV-bound chart selections, local source extraction and hashes, optional claim-to-source links and local review reports, notes, captions, image prompts and local attachment, manual multilingual import/export with source-freshness checks, consistency checks, feedback logs, structured revisions, protection baselines, output hashes/history, artifact freshness checks, local delivery bundles, actual PPTX validation, optional local rendering, stable-ID revision previews, slide PNGs, PDF and contact sheets. The [shared browser editor](session.md) adds live text editing, object positioning and styling, custom text/shapes/images, threaded comments, presence, revision conflicts, undo, and configurable agent proposals. Automated tests generate real bilingual decks and use no paid integrations.

Deliberate limits:

- No external image or AI translation adapter ships enabled. Interfaces, prompts and manual/local workflows are implemented; automatic image generation and automatic scientific translation are extension work.
- Document extraction is not automatic research synthesis. Except for literal Markdown plan import, an agent or person must author the content. Reference-image style analysis also requires an agent/person who actually inspects the images.
- Claim-to-source links are optional, authored records. A literal excerpt match checks traceability to local extracted text; it does not prove that the excerpt supports the claim, nor does it infer claims from slide text. The local claim report withholds excerpt text by default, but can still contain confidential slide wording and source paths.
- Advanced command help, errors and diagnostic details are mainly English. The first-run wizard and starter content support French and English. Other canonical BCP 47 output locales can be authored manually; the starter source content supports en-US and fr-FR.
- Text layout checks use conservative glyph-aware estimates, not PowerPoint font metrics. They can reject text that might fit or miss a font-specific issue. Long chart labels receive a review warning, but internal chart collisions still require full-size visual inspection. Object overlap checks cover logical content boxes; deliberate shape backgrounds/connectors are not independently collision-tested. Citations are printed verbatim; their bibliographic truth is not automatically verified.
- The built-in chart layout supports one native vertical-bar chart per slide; it does not provide a two-chart comparison layout. One message may require multiple coordinated visuals, but that editorial principle does not imply automatic support for every composition. CSV bindings copy finite numeric cells from explicit columns/rows, with at most 15 significant decimal digits; they do not compute transformations. The browser edits chart placement and supported appearance; values must be changed in their authoritative source. Table layout, other chart types, bibliography resolution, data transformations, OCR, automatic PPTX import/reconciliation and DOCX embedded image extraction are not included.
- Browser positioning and resizing preserve native PowerPoint objects. Browser font layout and chart previews approximate PowerPoint, so an exported render remains necessary for final visual review. Added shapes are rectangles; arbitrary vector paths, custom connectors, rotation, layered compositions, and unrestricted removal of generated source elements are not supported. Custom shape/text overlaps can be rejected by geometry validation. Missing custom text and image descriptions require explicit translation in each output language.
- Translation checks protect common numeric/unit/DOI notation and exact glossary terms. Fingerprints detect source changes after a recorded translation review; older translations without a fingerprint are flagged as untracked. These checks cannot establish semantic/scientific equivalence, parse all Unicode scientific notation, identify unchanged prose as necessarily mistranslated, or provide full RTL/CJK typography handling.
- Fictional charts receive a mandatory visible disclosure. English and French wording is built in; other locales require a manually supplied `fictionalNotice` in localized content, with scientific review of its wording. An omitted notice blocks export.
- Stored images are reused, but the PPTX is always reassembled as a whole. Builds report source changes; they do not implement partial ZIP regeneration or automatic pixel-quality judgments. Stable-ID previews provide before/after images for human inspection. Historical builds preserve source snapshots and earlier output decks, not a standalone hermetic copy of every dependency.
- Creator onboarding is enforced for newly created real projects; demo/legacy projects are backward compatible. The creator approval is a local, content-fingerprinted workflow safeguard, not cryptographic authentication. Agents must not forge approval; direct local YAML editing remains outside a security boundary. The setup interview is fixed-field rather than a fully adaptive conversational interviewer.
- Build protection baselines begin with the first successful build. The browser also checks current approval states and accepted images before the first export. YAML files remain directly editable; enforcement happens on revision/translation/image attachment and subsequent builds. A determined manual editor can bypass local state; these are workflow safeguards, not a security boundary. One session server owns a project and serializes its writes; connected clients can edit text concurrently through Yjs. While a session is active, use its editor and export controls. Outside a session, finish one CLI mutation before starting another against the same project.
- Collaboration requires a live connection to the session server. In-memory text generations, presence, movement locks and invitations reset on restart; YAML changes, feedback and history persist. The editor preserves conflicting drafts in the current browser page, but does not provide durable offline storage or merge arbitrary external YAML/PPTX edits. The HTTP server is intended for the local machine or a trusted private network, with no public hosting or encrypted transport built in. A configured agent executable is trusted local software; its external-service declarations do not sandbox its own capabilities.
- Rendering requires optional local software. LibreOffice and Windows PowerPoint use separate adapters; automated tests validate PPTX structure without requiring those applications. CI is configured for Linux, Windows and macOS on Node 22.13 and 24; the Linux Node 22.13 job renders a public typography matrix and uploads only PNG previews and a manifest for seven days. Selected full-size PowerPoint and LibreOffice images have been visually inspected; most matrix images still need human review. Generated files contain native title semantics, descriptive object names, localized image/chart descriptions and explicit decorative flags. PowerPoint's Accessibility Checker and Reading Order Pane were inspected programmatically through the UI accessibility tree on the English/French demo; a person has not visually reviewed those panes, and no screen reader was tested. Follow [the manual review checklist](accessibility-review.md) before delivery.
- PPTimistic distributes the reusable toolkit and fictional bilingual demo only. Private presentation sources, presentation-specific reference images and generated project outputs are excluded.

Next priority: have a person visually review the PowerPoint Accessibility Checker and Reading Order Pane, compare more Linux LibreOffice matrix slides against PowerPoint at full size, and improve font diagnostics only where rendered examples show false positives or missed overflow. Any future image or translation adapter needs explicit approval, a spending limit and local fixture tests.

PptxGenJS usage follows its official [chart API](https://gitbrent.github.io/PptxGenJS/docs/api-charts/) and [saving API](https://gitbrent.github.io/PptxGenJS/docs/usage-saving/). The lockfile and an `image-size` override retain patched dependencies; run `npm audit` when updating them.
